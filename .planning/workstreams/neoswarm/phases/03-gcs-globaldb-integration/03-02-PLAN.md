<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Remote CRDT delta → OnReputationElement | Untrusted network-originated bytes deserialized into NodeReputation |
| GcsGlobalDb → GossipPubSub topic | Reputation records published to the swarm; any peer can write to the topic |
| Consumer callback ← CRDT worker thread | Consumer code executes on a SuperGenius-owned thread |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Tampering | OnReputationElement deserialization | mitigate | ParseFromArray failure → log + drop; key prefix re-validated after pattern filter; malformed entries never reach consumer callbacks |
| T-03-06 | Spoofing | gcs-reputation topic writes | accept | Any swarm peer can publish reputation for any identity key in Phase 3; authenticated reputation attestation is a Phase 9 concern (recorded here for traceability) |
| T-03-07 | Denial of Service | Consumer callback on CRDT thread | mitigate | Doxygen contract: callbacks must be non-blocking; handlers are noexcept so consumer exceptions cannot crash the CRDT worker; callback registration is mutex-guarded |
| T-03-08 | Information Disclosure | QueryReputations fault tolerance | mitigate | Undeserializable entries are skipped with a warn log (key retained in log for operators) rather than failing the whole query or silently swallowed |
</threat_model>
