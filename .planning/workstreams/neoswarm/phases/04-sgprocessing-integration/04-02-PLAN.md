<objective>
Implement PROC-02 (FP4_ULTRA input format processor) as "wire + stub, ship what's ready" per D-08: re-enable FP4_ULTRA's commented-out schema validation branch in `ProcessingManager::CheckProcessValidity()`, and extend the existing `MNN_Tensor` processor (registered under `DataType::TENSOR`, per D-10's resolution that FP4_ULTRA stays TENSOR-typed rather than getting its own DataType) to recognize the FP4_ULTRA format and validate its buffer size/dimensions — without implementing any dequantization math (D-09) and without pretending MNN's E2M1 decode kernel is available, since it is not yet merged into the currently-linked MNN submodule (confirmed: `MNN_Ultra` branch has the kernel but is 39 commits diverged from the checked-out `master` snapshot, D-04/Q-02). The FP4_ULTRA branch of `MNN_Tensor::StartProcessing()` returns a structured `ProcessingError{FORMAT_UNSUPPORTED, ...}` describing this precisely, rather than crashing, silently degrading to garbage output, or duplicating dequant logic.

Purpose: Ship the FP4_ULTRA plumbing (schema validation + dispatch reachability) end-to-end now, so that once MNN's E2M1 kernel is merged (a separate, future phase per D-04), only the decode call site inside this same branch needs to change — the validation, dispatch, and error-handling contract are already correct and tested.
Output: FP4_ULTRA-formatted TENSOR jobs pass schema validation and reach `MNN_Tensor`; `MNN_Tensor` gives FP4_ULTRA a distinct, honest, structured failure path; existing tensor formats are unaffected; new unit tests prove both.
