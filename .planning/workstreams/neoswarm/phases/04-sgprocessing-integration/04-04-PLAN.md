<objective>
Complete D-06's "duplicate raw-MNN-invocation logic is removed from NEO-SWARM" directive: delete `MNNInferenceEngine::InferViaStandardInterpreter()`, `RunForward()`, `SampleToken()`, and `ApplyRepetitionPenalty()` — the hand-rolled ~150-line autoregressive sampling loop that duplicates what the new SGProcessingManager `MNN_Llm` processor (plan 04-03) now does correctly via MNN's own native API. Since these four functions are also the sole callers of `StreamInfer()`'s "interpreter" mode fallback branch and of `LoadModel()`'s "standard single-file .mnn model (non-LLM)" sub-path, this plan mechanically completes the same deletion in both of those call sites rather than leaving them referencing now-deleted functions or holding now-fully-orphaned state (`m_interpreter`, `m_session`, `SelectBackend()`). `InferViaMnnLlm()` (native `MNN::Transformer::Llm` usage) and `InferViaSGProcessing()` (the in-process `ProcessingManager` call path) are explicitly NOT touched — D-06 keeps both.

Also completes D-13: removes the confirmed-orphaned `fp4::FP4Codec m_fp4Codec` member (and its `(void) m_fp4Codec;` discard) from `MNNInferenceEngine`, since this phase's PROC-02 work (plan 04-02) does not build around NEO-SWARM's own dead NF4-style codec — it targets MNN_Ultra's E2M1 format via SGProcessingManager instead, per D-13's locked resolution. `fp4_codec.hpp`/`.cpp` themselves and their standalone `test_fp4_codec` test target are left in place (not deleted) — this task only removes the one confirmed-orphaned reference inside `MNNInferenceEngine`, not the whole class/file, since a full-file removal is a separate, bigger decision this phase does not make unilaterally.

Finally, adds FP4_ULTRA and LLM-oriented job-schema test cases to `test/integration/test_sgprocessing_pipeline.cpp`, using the same `HasUsableVulkanDevice()`-based skip-gate pattern already established in SuperGenius's own `capture_smoke_test.cpp` — proving these cases run to completion instead of silently hanging on this exact Windows machine (confirmed real Vulkan device present, which triggers the pre-existing, tracked, out-of-scope `VulkanInitMutex` re-entrancy deadlock in `ProcessingManager::Create()`, sgproc-render's own Phase 18).

Purpose: Finish the consolidation this phase's requirements call for, without leaving dead code behind or silently regressing test coverage into an indefinite hang.
Output: `mnn_inference_engine.cpp`/`.hpp` contain only the two supported inference paths (`InferViaSGProcessing`, `InferViaMnnLlm`) plus stub mode; the orphaned FP4 codec member is gone; new integration test cases exist and are honest about the known Vulkan blocker.
</objective>
