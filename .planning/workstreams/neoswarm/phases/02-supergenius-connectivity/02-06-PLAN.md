    **Per SG-02 requirement:** Replace the stub `SubmitNetwork()` in `src/core/sgprocessing/sg_processing_bridge.cpp` (lines 355-366) with a real implementation that dispatches via SGClient.

    Current code (lines 355-366):
    ```cpp
    outcome::result<std::vector<uint8_t>> SGProcessingBridge::SubmitNetwork( const std::string& jsondata ) const
    {
        if ( !m_client )
        {
            BridgeLogger()->error( "SubmitNetwork: SGClient not configured" );
            return outcome::failure( Error::NetworkError );
        }
        BridgeLogger()->debug( "Submitting job via SGClient ({} bytes)", jsondata.size() );
        (void)jsondata;
        return outcome::failure( Error::NetworkError );
    }
    ```

    Replace with:
    ```cpp
    outcome::result<std::vector<uint8_t>> SGProcessingBridge::SubmitNetwork( const std::string& jsondata ) const
    {
        if ( !m_client )
        {
            BridgeLogger()->error( "SubmitNetwork: SGClient not configured" );
            return outcome::failure( Error::NetworkError );
        }

        if ( !m_client->IsConnected() )
        {
            BridgeLogger()->warn( "SGClient not connected — attempting dispatch anyway" );
        }

        BridgeLogger()->info( "Submitting job via SGClient ({} bytes)", jsondata.size() );
        return m_client->SubmitJob( jsondata );
    }
    ```

    The existing `SubmitJob()` method in `sg_processing_bridge.cpp` (lines 246-280) already has the auto-fallback logic:
    - If `m_cfg.m_networkMode` is true → calls `SubmitNetwork()`
    - On failure (not SignatureInvalid/IdentityError) → auto-falls back to `SubmitDirect()`
    This auto-fallback logic is unchanged — it now works correctly because `SubmitNetwork()` delegates to the real `SGClient::SubmitJob()`.
