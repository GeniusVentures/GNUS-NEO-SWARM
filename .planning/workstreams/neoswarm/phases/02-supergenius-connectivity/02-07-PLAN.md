    **Step A — Verify SGClient::SubmitJob() passes 120s timeout:**

    In `src/network/sg_client/super_genius_client.cpp` (lines 80-112), the `SubmitJob()` method already calls:
    ```cpp
    auto result = m_impl->resultCollector_->WaitForResult( taskId, m_impl->m_cfg.result_m_timeout );
    ```
    After Plan 02-05, `result_m_timeout` defaults to 120s and the SGResultCollector polling loop enforces it with `std::chrono::steady_clock::now() < deadline`. **No changes needed** — the deadline is already enforced by the polling loop.

    However, add a clear log line to make the deadline explicit. Insert after line 102 (`ClientLogger()->info(...)`):
    ```cpp
    ClientLogger()->info("Job {} waiting for result (deadline={}s)", taskId, m_impl->m_cfg.result_m_timeout.count());
    ```

    **Step B — Verify auto-fallback in SGProcessingBridge::SubmitJob():**

    In `src/core/sgprocessing/sg_processing_bridge.cpp` (lines 246-280), the auto-fallback logic is:
    ```cpp
    if (m_cfg.m_networkMode)
    {
        auto result = SubmitNetwork(json_res.value());
        if (!result.has_value())
        {
            // Auto-fallback to local MNN on network failure
            // Auth failures are NOT silently swallowed
            if (result.error() == Error::SignatureInvalid || result.error() == Error::IdentityError)
            {
                BridgeLogger()->error("Network dispatch auth failed — NOT falling back to local mode");
                return result;
            }
            BridgeLogger()->warn("Network dispatch failed ({}), falling back to local mode",
                                  result.error().message());
            return SubmitDirect(json_res.value(), ioc);
        }
        return result;
    }
    ```
    This logic already handles the fallback correctly. The only thing to verify: after Plan 02-05, `SubmitNetwork()` (Plan 02-06) calls `m_client->SubmitJob()` which can return `BroadcastTimeout` (on 120s expiry) or `NetworkError`. Both will trigger the fallback.

    **Add an explicit check for BroadcastTimeout** to produce a more informative log:
    After the `!result.has_value()` check, add:
    ```cpp
    if (result.error() == Error::BroadcastTimeout)
    {
        BridgeLogger()->warn("SG dispatch timed out after {}s — falling back to local mode",
                              m_client ? "120" : "unknown");
    }
    ```
    Insert this before the existing auth-failure check.

    **Acceptance criteria:**

    - `grep -c "BroadcastTimeout" src/core/sgprocessing/sg_processing_bridge.cpp` shows `>= 1`
    - `grep -c "SubmitDirect.*fallback\|fallback.*SubmitDirect" src/core/sgprocessing/sg_processing_bridge.cpp` shows `>= 1`
  </action>
