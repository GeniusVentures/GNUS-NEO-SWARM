**Part B: Add _validate_fp4_export() to ConfigLoader**

Add a `_validate_fp4_export(self) -> None` method following the exact pattern of `_validate_teacher()`. Validation rules per RESEARCH.md Pitfall 5:

1. **fp4_export block exists and is a dict.** If missing, log a warning (not a hard error) because Phase 1/2 may run without quantization. If present but not a dict, raise ConfigValidationError("fp4_export", "must be a dictionary").

2. **Required block sizes in error_thresholds.** The keys 64, 32, 16, 8, 4 must all be present (as integers or string representations). If any is missing, raise ConfigValidationError(f"fp4_export.error_thresholds", "missing required block size: {size}").

3. **Each threshold entry is a dict with max_mse and max_relative.** Both must be present. Both must be positive numbers (> 0.0). Raise ConfigValidationError on negative or zero values with the specific key path (e.g., "fp4_export.error_thresholds.64.max_mse").

4. **ternary_delta is in range [0.0, 1.0].** Raise ConfigValidationError otherwise.

5. **min_block_size is one of {4, 8, 16, 32, 64}.** Power-of-2 check is sufficient. Raise ConfigValidationError otherwise.

6. **laplacian_levels is a positive integer >= 1.** Raise ConfigValidationError otherwise.

7. **log_mode_enabled is a boolean.** Raise ConfigValidationError otherwise.

Add the call `self._validate_fp4_export()` to the `_validate()` method, immediately after `self._validate_pipeline_specialists()`.

**Check 5: magic_header_valid** (only if .sgfp4 exists)

Read the first 5 bytes of the .sgfp4 file. Verify:
- Bytes 0-3 = `b'SGF4'` (magic header)
- Byte 4 = `0x02` (SGFP4 v2 version)

If magic mismatch: `{"name": "magic_header_valid", "passed": False, "detail": f"Expected b'SGF4', got {actual_magic}"}`
If version mismatch: `{"name": "magic_header_valid", "passed": False, "detail": f"Expected version 0x02, got {actual_version}"}`
If both correct: `{"name": "magic_header_valid", "passed": True, "detail": "Magic SGF4 + version 0x02"}`

Use binary read (`open(sgfp4_path, 'rb')`) with a try/except for OSError.

**Check 6: manifest_sha256_valid** (if manifest.json and .sgfp4 both exist)

Read manifest.json, extract the `fp4_binary.sha256` field. Compute SHA256 of the .sgfp4 file using hashlib.sha256() (reuse the pattern from ManifestBuilder._file_sha256). Compare:
- Match: `{"name": "manifest_sha256_valid", "passed": True, "detail": "SHA256 matches"}`
- Mismatch: `{"name": "manifest_sha256_valid", "passed": False, "detail": f"Manifest SHA256 {manifest_hash} does not match file SHA256 {file_hash}"}`

If `fp4_binary` or `sha256` key is missing from manifest, pass with detail "No sha256 field in manifest" (not a hard failure for backward compat).

**Check 7: manifest_required_fields** (if manifest.json exists)

Validate QUANT-03 required fields: model_name, niche, base_model_ref, adapter_ref, quantization_params, encoder_version, timestamp_utc. Report any missing fields.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pipeline.yaml filesystem -> ConfigLoader | YAML file parsed with yaml.safe_load; numeric validation prevents injection |
| SGFP4 binary filesystem -> CheckpointValidator | Binary file read for magic header; path constructed from trusted niche_name |
| manifest.json filesystem -> CheckpointValidator | JSON parsed with json.loads; SHA256 field cross-validated against binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Tampering | pipeline.yaml fp4_export values | mitigate | ConfigValidationError on negative MSE, out-of-range delta, invalid block sizes; all numeric fields validated at load time per D-08 |
| T-03-07 | Denial of Service | CheckpointValidator reading large .sgfp4 | mitigate | SHA256 computed in 64KB chunks (io.DEFAULT_BUFFER_SIZE pattern); no full file read into memory; timeout not needed (file is < 100MB for POC) |
| T-03-08 | Spoofing | manifest SHA256 validation | mitigate | Checkpoint verifies SHA256(manifest claim) == SHA256(binary file); mismatch fails the check with both hashes in detail; prevents manifest-tampered-but-binary-intact attacks |
| T-03-09 | Information Disclosure | ConfigValidationError messages | accept | Error messages reference config key paths and expected types; no secrets, no weight values, no API keys. Low risk. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; pyyaml already verified via slopcheck [OK] |
</threat_model>
