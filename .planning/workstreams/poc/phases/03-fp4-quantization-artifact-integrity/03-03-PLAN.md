<objective>
Create MetricStore for structured persistence of SGFP4 quantization metrics (per-block MSE, effective bitrate, T158 ratio) and extend Benchmarker with a gate_check() method that evaluates SGFP4 metrics against configurable per-dimension thresholds following the Phase 2 auto-gating pattern. This implements D-09: SGFP4 error metrics become gate dimensions in eval_gates.

Purpose: Enable the pipeline to automatically reject quantized models whose SGFP4 quality metrics fall below configurable thresholds, preventing sub-par weight encodings from reaching the benchmark evaluation stage (Phase 4). The gate dimensions follow the same pattern as Phase 2 evaluation gating to maintain a consistent quality control surface.

Output: `eval/metric_store.py` (new), `eval/benchmarker.py` (extended with gate_check).
</objective>

  <name>Task 1: Create MetricStore for SGFP4 quantization metric persistence</name>
  <files>

  <action>
Create `gnus-poc/eval/metric_store.py` with a `MetricStore` class that persists SGFP4 quantization metrics in a structured, queryable format. This follows the pattern established by the existing eval modules (SpecialistEvaluator writes to `artifacts/evaluations/`).

**Class: MetricStore**

Constructor `__init__(self, project_root: Optional[Path] = None)`:
- Self-locates project root if None (following existing pattern in benchmarker.py line 12-13)
- Sets `self._metrics_dir = project_root / "artifacts" / "evaluations"` for output
- Creates metrics_dir on init (mkdir parents=True, exist_ok=True)

**Method: record_sgfp4_metrics(self, niche_name: str, fp4_stats: dict, **kwargs) -> Path:**

Records SGFP4 quantization metrics for a specialist niche/run. Input `fp4_stats` is the stats dict from FP4Exporter.export_to_file (see interfaces above for format).

Extracts and computes these gate-relevant metrics:
- `fp4_mse`: Compute as weighted average from layout_distribution. Use per-block-size MSE estimates: the mismatch between the stats format and the needed metrics is handled by computing an aggregate from available data. If the stats dict contains a `per_block_errors` field (mean squared error per block), use that. Otherwise: use `effective_bpw` deviation from target (4.0) as a proxy: `fp4_mse = max(0.0, (effective_bpw - 2.5) / 100.0)`. Document the proxy in the code comment and mark it for replacement when `per_block_errors` is available from Phase 4 benchmark data.
- `fp4_effective_bitrate`: Directly from `fp4_stats["effective_bpw"]`.
- `fp4_t158_ratio`: Compute as `fp4_stats["t158_blocks"] / (fp4_stats["fp4_blocks"] + fp4_stats["t158_blocks"])` if total blocks > 0, else 0.0.

Writes a JSON file to `{metrics_dir}/{niche_name}_sgfp4_metrics.json` with:
```json
{
    "niche": niche_name,
    "timestamp_utc": "ISO 8601",
    "quantization_metrics": {
        "fp4_mse": float,
        "fp4_effective_bitrate": float,
        "fp4_t158_ratio": float
    },
    "raw_stats": { /* the full fp4_stats dict for auditability */ }
}
```

Returns the Path to the written file.

**Method: load_sgfp4_metrics(self, niche_name: str) -> Optional[dict]:**

Loads the most recent SGFP4 metrics file for a given niche. Globs `{metrics_dir}/{niche_name}_sgfp4_metrics.json`. Returns the parsed dict or None if no file exists. Sorts by filename (timestamps in ISO 8601 sort naturally) and returns the last one.

**Method: list_all_metrics(self) -> Dict[str, dict]:**

Globs all `*_sgfp4_metrics.json` files. Returns dict mapping niche_name -> metrics dict. Useful for gate_check to evaluate all specialists at once.

**Integration note:** MetricStore is a new class, not an extension of any existing class. It does not depend on SpecialistEvaluator or Benchmarker. It reads the stats.json produced by FP4Exporter (Plan 03-01) but is independent of it — the import of fp4_exporter stats format is by contract (dict shape), not by code import.

**Method: gate_check(self, niche_name: str, config: dict) -> dict:**

Accepts:
- `niche_name`: specialist niche to evaluate
- `config`: the effective config dict (from ConfigLoader.get_effective_config(niche_name)) containing the `eval_gates` block

Returns a dict:
```python
{
    "niche": str,
    "passed": bool,           # True iff all dimensions pass
    "checks": [               # one per gate dimension
        {
            "dimension": "fp4_mse",
            "value": float,
            "threshold": {"max": float, "consecutive_failures_to_block": int},
            "passed": bool,
            "detail": str
        },
        ...
    ],
    "blocking": bool,         # True if any dimension has hit consecutive_failures_to_block
    "consecutive_failures": {dimension: count}
}
```

Logic:
1. Extract `eval_gates` from config. If missing, return `{"passed": True, "checks": [], "blocking": False, "detail": "No eval_gates configured"}`.
2. Load SGFP4 metrics via MetricStore: `self._metric_store.load_sgfp4_metrics(niche_name)`. If no metrics exist (quantize stage not yet run), return `{"passed": True, "checks": [], "blocking": False, "detail": "No SGFP4 metrics available yet"}`.
3. For each SGFP4 gate dimension in config (fp4_mse, fp4_effective_bitrate, fp4_t158_ratio):
   - Extract actual value from metrics
   - Compare against threshold (max for mse/bitrate, min for t158_ratio)
   - Record pass/fail with descriptive detail (e.g., "fp4_mse 0.012 exceeds max 0.01")
4. Track consecutive failures: load the previous gate_check result file (if exists), increment counters for failing dimensions, reset counters for passing dimensions. Persist the updated counters.
5. Determine blocking: if any dimension's consecutive_failures >= its `consecutive_failures_to_block`, set blocking=True.
6. Return the result dict.

**Persist gate state:**

Add `self._gate_state_dir = project_root / "artifacts" / ".gate_state"`. Store per-niche gate check history as `{niche_name}_gate_state.json`:

```json
}
```

The existing `compare_variants()`, `save_comparison()`, and `print_comparison_table()` methods are unchanged. The new `gate_check()` method is additive. Existing callers that do not pass `config` are unaffected (gate_check simply returns "no config" pass).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fp4 stats.json -> MetricStore | JSON file on filesystem; parsed with json.loads; values validated for expected types |
| eval_gates config -> Benchmarker.gate_check | Config values loaded from pipeline.yaml via ConfigLoader (already validated); thresholds assumed valid |
| gate_state.json filesystem -> Benchmarker | JSON read/write for consecutive failure tracking; no user input in path construction |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | metric_store.py stats ingestion | mitigate | Validate fp4_stats dict keys before access; handle missing keys with default values and warning logs; reject non-numeric metric values |
| T-03-11 | Denial of Service | gate_state.json corruption | mitigate | Wrap JSON read/write in try/except; corrupt state files are deleted and recreated fresh; gate defaults to passing when state is unreadable (fail-open for POC) |
| T-03-12 | Tampering | eval_gates config threshold manipulation | mitigate | Thresholds loaded from pipeline.yaml via ConfigLoader (safe_load); numeric bounds checked in ConfigLoader (Plan 03-02); gate_check validates threshold dict structure before comparing |
| T-03-13 | Spoofing | consecutive_failure counter manipulation | mitigate | Gate state stored in artifacts/.gate_state/ (not user-writable during normal pipeline execution); SHA256 not needed for POC gate state (non-security-critical metadata) |
| T-03-14 | Information Disclosure | gate_check result detail strings | accept | Result detail contains metric names, values, and thresholds — all non-sensitive quantization quality data. No weights, no model parameters, no API keys. |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; json, pathlib, and hashlib are stdlib |
