  <action>
Create two new modules that together provide all the encode-side analysis for adaptive block-size selection. These modules have zero dependencies on each other and are consumed by FP4Exporter in Task 2.

**laplacian.py** — LaplacianWeightedError class for encode-side error analysis per D-07:

- Single public method `compute(original_2d: np.ndarray, reconstructed_2d: np.ndarray, block_size: int) -> float` that returns Laplacian-weighted MSE.
- Adapt pyramid levels to block size per RESEARCH.md Pitfall 2: 4x4 and 8x8 blocks skip Laplacian entirely (use plain `np.mean(residual**2)`), 16x16 uses 1 level, 32x32 uses 2 levels, 64x64 uses 3 levels.
- For leveled computation: use `scipy.ndimage.gaussian_filter` with `sigma=2**level` and `mode='reflect'`. At each level compute `smooth_base = gaussian_filter(smooth, sigma=sigma, mode='reflect')`, weight error by `1.0/(2**level)`, downsample both `smooth` and `residual` by `[::2, ::2]` for next level.
- Return `total_error / weight_sum` if weight_sum > 0, else fall back to `float(np.mean(residual**2))`.
- Accept sigma and mode as constructor kwargs with defaults per RESEARCH.md Pattern 2 for tunability.
- All numpy operations in float32 to match weight tensor precision.

**quadtree.py** — QuadtreeEncoder class implementing D-01 full quadtree recursion:

- Constructor receives `thresholds: dict` (mapping block_size->{max_mse, max_relative}), `ternary_delta: float`, `min_block_size: int=4`.
- Single entry point `encode(superblock_64x64: np.ndarray) -> List[dict]` where each dict is `{y, x, size, mode, payload, header, scale, bias, error}`.
- Internally calls `_try_block(superblock, y, x, size) -> List[dict]` which is recursive per D-01:
  1. Extract `region = superblock[y:y+size, x:x+size]`
  2. Fit both FP4_AFFINE and T158_AFFINE on region (using the fit/encode logic from fp4_exporter.py — pass as constructor dependency `encoder: FP4Exporter` or callable hooks)
  3. Compute Laplacian-weighted error for both modes using LaplacianWeightedError
  4. Select mode per D-04: prefer T158 when `t158_error <= (1.0 + ternary_delta) * fp4_error`
  5. Apply per-weight max error guard for T158 per RESEARCH.md Pitfall 4: if any individual weight reconstruction error exceeds `5 * scale`, reject T158 and force FP4_AFFINE regardless of aggregate error
  6. Check error threshold: if `selected_error <= threshold.max_mse` OR `size <= min_block_size`, ACCEPT block at this size — return single-element list
  7. Otherwise SPLIT: `half = size // 2`, recurse on `(y, x)`, `(y, x+half)`, `(y+half, x)`, `(y+half, x+half)`, concatenate results
- Apply hysteresis per RESEARCH.md Pitfall 1: if parent block was accepted (error <= threshold), require child error to be `<= threshold * 0.8` (20% improvement) before splitting. If error > threshold but `<= threshold * 1.1` (10% slack) and min_block_size not reached, accept the block.
- Max recursion depth = 4 levels (64->32->16->8->4). Raise ValueError if reached (should never happen due to min_block_size guard).

The encode hooks for FP4_AFFINE/T158_AFFINE fitting: QuadtreeEncoder accepts `fit_fp4: Callable` and `fit_t158: Callable` constructor args. In Task 2, FP4Exporter passes its own `_encode_fp4_affine` and `_encode_t158_affine` adapted for variable block sizes (not the fixed-4096-item v1 versions). Document this contract in module docstrings.

Expose both classes via `quantize/__init__.py` imports.

  <name>Task 2: Upgrade FP4Exporter to SGFP4 v2 with variable blocks, superblock layout, and backward compatibility</name>

  <action>
Extend the existing FP4Exporter class to support both v1 fixed and v2 adaptive export paths. The v1 path (existing `export_weights` and `_encode_*` methods) is preserved as-is for backward compatibility. New methods are added for v2.

**Add v2 internal encode methods (variable block sizes):**

Add `_encode_fp4_affine_variable(self, region: np.ndarray) -> dict` and `_encode_t158_affine_variable(self, region: np.ndarray) -> dict`. These replicate the existing `_encode_fp4_affine`/`_encode_t158_affine` logic but operate on variable-sized regions (not hardcoded to 4096 elements). Key differences from v1:
- Flatten `region` (any N×N size), compute `n_weights = region.size`
- Payload packing uses `n_weights // 8` uint32s for FP4 and `n_weights // 16` uint32s for T158
- `_fit_affine` and `_fit_ternary` are reused unchanged (they operate on 1D arrays)
- Return dict: `{scale, bias, l2_error, payload, n_weights}`

**Add payload size helper:**

Add `_payload_u32(self, size: int, mode: int) -> int` per D-03 and RESEARCH.md Code Examples:
- FP4_AFFINE: `(size * size) // 8` uint32 words
- T158_AFFINE: `(size * size) // 16` uint32 words

**Add superblock layout enum constants (D-02):**

```python
LAYOUT_UNIFORM_64 = 0    # one 64x64 block
LAYOUT_UNIFORM_32 = 1    # four 32x32 blocks
LAYOUT_UNIFORM_16 = 2    # sixteen 16x16 blocks
LAYOUT_UNIFORM_8  = 3    # sixty-four 8x8 blocks
LAYOUT_MIXED      = 4    # mixed quadtree
LAYOUT_FULL_4x4   = 5    # full 4x4 stamps (256 blocks)
```

**Add layout classification:**

Add `_classify_layout(blocks: List[dict]) -> int` that examines block sizes from quadtree output and returns the layout enum:
- All blocks same size 64 -> LAYOUT_UNIFORM_64
- All blocks same size 32 -> LAYOUT_UNIFORM_32
- All blocks same size 16 -> LAYOUT_UNIFORM_16
- All blocks same size 8 -> LAYOUT_UNIFORM_8
- All blocks same size 4 -> LAYOUT_FULL_4x4
- Mixed sizes -> LAYOUT_MIXED

**Add SGFP4 v2 binary format (4-byte magic + version):**

Per RESEARCH.md recommendation, add a 4-byte magic header at file start: `b'SGF4'` (0x53 0x47 0x46 0x34). Follow with a 1-byte version: `0x02` for SGFP4 v2. Then superblock offset table and superblock data.
- Magic + version = 5 bytes total before superblock data

**Add superblock offset table:**

After magic header, write `B` uint32 offsets (one per superblock) pointing to each superblock's data. This satisfies the paging requirement in D-03 (fixed container per 64x64 superblock, variable total size across superblocks).

**Add _export_v2_adaptive method:**

`_export_v2_adaptive(self, weights, niche_name, thresholds, ternary_delta, laplacian_levels, min_block_size, prefer_ternary) -> Tuple[bytes, dict]`:
1. Pad weights to multiples of 64 (reuse existing logic)
2. Split into 64x64 superblocks (reuse existing tiling logic)
3. For each superblock:
   a. Instantiate LaplacianWeightedError and QuadtreeEncoder
   b. Call `quadtree.encode(superblock)` -> list of block dicts
   c. Classify layout with `_classify_layout(blocks)`
   d. Pack superblock header uint32: `layout[2:0] | (reserved << 3) | (fp16_scale << 16) | fp16_bias` — where scale/bias are computed as the per-superblock average of per-block scales/biases for uniform layouts, or per-block scale/bias stored in per-block headers for mixed layouts
   e. Per D-06: each block gets a per-block header uint32 = `_pack_half2(block["scale"], block["bias"])` with 4 LSB offset flags: bit 0 = mode (FP4=0, T158=1), bit 1 = log mode (reserved=0 per D-05), bits 2-3 = reserved (0)
   f. Serialize per-block payloads with 16-byte alignment per RESEARCH.md Pitfall 3: `aligned_size = (payload_size + 15) & ~15`
   g. Accumulate offsets into per-superblock codes_blob
4. Assemble binary: magic + version + superblock_offset_table + concatenated superblock data
5. Return (binary, stats)

**Add _export_v1_fixed method:**

Preserves existing v1 behavior exactly. Callable via `export_weights(weights, niche_name, prefer_ternary=False, ternary_delta=0.10, adaptive=False)`. When `adaptive=False`, output uses `.fp4` extension (no magic header). When `adaptive=True`, output uses `.sgfp4` extension with magic header per RESEARCH.md backward compatibility strategy.

**Upgrade export_weights to dispatch:**

Add `adaptive: bool = False` parameter. When `False`: delegate to existing v1 logic (inlined, no change to existing behavior). When `True`: delegate to `_export_v2_adaptive`. Accept additional kwargs: `thresholds`, `min_block_size`, `laplacian_levels` (passed through to v2).

**Upgrade export_to_file to write manifest per D-10 and QUANT-03:**

After writing binary, import and call `ManifestBuilder.build()` with:
- `model_name` from `niche_name`
- `base_model` from `kwargs.get('base_model', '')` 
- `training_metadata` from `kwargs.get('training_metadata', {})`
- `fp4_bin_path` = path to written binary
- `fp4_stats` = stats dict from export
- Write manifest.json alongside binary using `ManifestBuilder.save()`

Also write `{niche_name}_stats.json` with extended fields: `shape`, `num_superblocks`, `layout_distribution` (counts per layout enum value), `fp4_blocks`, `t158_blocks`, `effective_bpw` (total bits / total weights), `total_bytes`.

**Update module docstring:**

Replace the v1 docstring with description of both v1 (fixed 64x64) and v2 (adaptive quadtree with variable blocks) modes.

**Ensure backward compatibility:**

The existing `__main__` block (lines 204-228) and `export_to_file` default path produce v1 output unchanged. Tests that call `fp4_exporter.py --niche code` must produce identical binary to before this upgrade. Only code paths behind `adaptive=True` activate v2 behavior. The existing inlined manifest generation in `__main__` (lines 217-227) is replaced by the ManifestBuilder call path.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| weight tensor input -> FP4Exporter | Untrusted user-supplied numpy array (shape, dtype, values) |
| pipeline.yaml -> ConfigLoader | YAML file on filesystem; parsed with yaml.safe_load |
| output file path -> filesystem | niche_name used in path construction; path traversal risk |
| binary output -> consumer | SGFP4 binary consumed by C++ decoder; malformed layout enum = decoder crash |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | QuadtreeEncoder._try_block() | mitigate | Validate tensor dimensions before encode; enforce max recursion depth of 4 (hard constant); reject empty/NaN tensors at entry |
| T-03-02 | Tampering | export_to_file output path | mitigate | Validate niche_name against allowed specialist list from config; use pathlib for safe path construction; reject path traversal characters (../) |
| T-03-03 | Tampering | fp4_exporter.py binary output | mitigate | Include 4-byte magic header + version byte for format detection; superblock offset table validated at decode; manifest SHA256 enables integrity verification |
| T-03-04 | Information Disclosure | stats.json output | accept | Stats contain aggregate counts (layout distribution, bpw, block counts), no weight values exposed. No PII. |
| T-03-05 | Elevation of Privilege | ManifestBuilder | accept | ManifestBuilder writes to artifacts/manifests/ via pathlib; no shell execution; SHA256 uses stdlib hashlib (no custom crypto) |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed; numpy, scipy, pyyaml already verified via slopcheck [OK] per RESEARCH.md Package Legitimacy Audit |
