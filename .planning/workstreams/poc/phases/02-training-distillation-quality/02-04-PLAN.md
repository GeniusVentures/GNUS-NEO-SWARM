<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Specialist config YAML -> Gate checker | Threshold values loaded from config — misconfiguration could bypass quality gates |
| Evaluation metrics -> Gate state | Metric values persist to gate state files — tampering could suppress failure detection |
| Previous metrics -> Delta computation | Loaded from artifacts/evaluations/ — missing previous file treated as first run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-15 | Tampering | eval/benchmarker.py gate state persistence | mitigate | Gate state file (artifacts/.gate_state/{niche}_training_gate_state.json) records history (consecutive_failure counters + timestamps). Fail-open on corrupt files (consistent with Phase 3/4 pattern). Separate from SGFP4 and benchmark gate state files — no gate family interference. |
| T-02-16 | Repudiation | eval/benchmarker.py gate blocking | mitigate | Every gate check result recorded in gate state with timestamp. Consecutive failure counters provide audit trail. Blocked=True only after N consecutive failures — provides defense against "why was this blocked?" disputes. |
| T-02-17 | Denial of Service | eval/metric_store.py JSON persistence | mitigate | Fail-open on corrupt metric files (returns None, logs warning). JSON file sizes bounded by fixed metric schema (< 1 KB per record). No unbounded file growth — one file per run. |
| T-02-18 | Elevation of Privilege | eval/benchmarker.py gate bypass | mitigate | Per D-17: auto-gating only blocks after N consecutive failures. Single failures log and continue — but this is DESIGNED BEHAVIOR (prevents flaky-run false blocks). The consecutive_failures_to_block config enforces eventual blocking for persistent failures. Gate state persistence prevents counter reset on pipeline restart (Pitfall 5). |
| T-02-19 | Information Disclosure | eval/evaluator.py metric persistence | accept | Evaluation metrics (PPL, BLEU, ROUGE-L, latency) are training metrics — not sensitive. No PII or secrets in persisted JSON. |
| T-02-20 | Tampering | config/specialists/*.yaml threshold values | mitigate | Config loaded via yaml.safe_load(). Gate thresholds validated for type (float/int) and range (> 0 for max values, 0.0-1.0 for rates). Invalid thresholds caught at load time. |
| T-02-SC | Tampering | pip install | mitigate | No new package installs in this plan. All dependencies already installed. |
</threat_model>
