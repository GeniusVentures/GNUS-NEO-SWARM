    `ConfigLoader.__init__(self, project_root: Path)`:
    - Loads `config/pipeline.yaml` as the global config via yaml.safe_load
    - Loads all YAML files in `config/specialists/*.yaml` as specialist configs

    Validation (called during __init__, after loading):
    - Every `endpoints` entry must have: `url` (string), `apiType` (one of "openai", "anthropic")
    - Every `models` entry must have: `endpoint` (string matching an endpoints key), must also have `model_id` field OR default to the model key itself
    - `teacher.level1` must match a key in `models`
    - `teacher_benchmark` domain keys must be strings mapping to dicts of model_name → float scores; every model_name must exist in `models`
    - `pipeline.specialists` must be a non-empty list of strings
    - On validation failure: raise ConfigValidationError with message including the YAML key path (e.g., "endpoints.litellm: missing required field 'url'")

    Per-specialist override resolution method `get_effective_config(self, niche: str) -> dict`:
    - Start with a deep copy of the global config
    - If a specialist config exists for `niche`, deep-merge its values over the global defaults
    - Deep-merge rules: dict values merge recursively (specialist keys override global keys at same level); list values replace (not concatenate); scalar values replace
    - The specialist config key `specialist.base_model` overrides `training.base_model` in the effective config
    - The specialist config key `specialist.training.*` overrides corresponding `training.*` keys
    - The specialist config key `specialist.system_prompt` and `specialist.synthetic_prompts` are available as top-level keys in the effective config
    - Raise ConfigValidationError if `niche` is not in `pipeline.specialists` (with a message naming the valid options)

    Update `config/__init__.py` to export: `from config.loader import ConfigLoader, ConfigValidationError`
  </action>
